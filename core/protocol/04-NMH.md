# NMH：人↔Agent 协作探索协议

> v1.0
> **一句话**：人给的是方向，不是需求。NMH 是人和 Agent 一起把模糊方向变成**锁定的决策树**的过程，同时是人的学习通道。
> **设计出处**：核心审讯机制（逐分支决策树审讯、一次一问、附推荐答案、术语对齐、即时落盘、克制的升级）逐字继承自 QwenPaw 社区 skill `grill-me` / `grill-with-docs`——逐条对照见 [../../ACKNOWLEDGMENTS.md](../../ACKNOWLEDGMENTS.md) §1（原稿归档于 `docs/provenance/grill/`）。探索/锁定双模式、锁定前七问自检、结构化 spec 输出为 Millforge 扩展。

## 1. 触发规则

**核心规则：谁收到 human 的消息，谁调 NMH——与角色无关，与人有关。**

**强制触发**（满足任一）：
- 需求含方案/设计/评估/迁移/选型/对比/重构/规划类词汇
- 需求含隐含决策点（"优化一下"——优化什么维度？边界在哪？）
- human 主动表达"我不确定 / 你觉得呢 / 有没有别的方案"

**不触发**（直接执行/回答）：简单查询 / 三要素已完整的明确指令 / 状态查询 / 纯确认。

**触发判断错误的代价不对称**：该触发没触发 = 做偏整个任务（重做）不该触发触发了 = 多几轮问答（浪费）。拿不准 → 触发。

## 2. 双模式动态切换

| 模式 | 状态 | 行为 |
|------|------|------|
| **探索模式** | 需求边界未知 | 无固定决策点。自由 Q&A + 知识分享，边聊边画决策树骨架。判断人的知识深度，给恰到好处的解释（不预设"人不懂"也不预设"人全懂"） |
| **锁定模式** | 决策树骨架清晰（节点 ≥3 且无重大未知） | 逐节点锁定：选项 + 推荐 + 理由，human 确认/修改/否决 |

模式不是状态机硬切换——锁定中发现新未知 → 回到探索。

## 3. Phase 1：理解

1. **知识深度判断**：从措辞、历史交互（读旧 NMH 文档的学习摘要）判断储备 → 决定解释深度
2. **读现有文件**：本领域已有决策树、handoff、charter——不重复问已锁定的事
3. **术语消歧**：检测到歧义当场指出、统一，记入术语对齐日志
4. **画决策点骨架**：3-8 个决策点，标依赖关系
5. **自检**：骨架里有没有**断言无法给出来源**的决策点？（🏳️ 候选——判定标准见 §7）

## 4. Phase 2：交互循环

**问题格式（每个决策点）**：

```
[D{n}] {决策主题}
  选项: A: ... / B: ...
  推荐: {A/B} — 理由: {一句话}
  影响: {选错的话会怎样}
```

**drill-deeper 条件**（回应不满足任一 → 追问，最多两轮）：未覆盖所有选项 / 引入新术语 / 与已锁定节点冲突。

**纪律**：一次一个问题（探索模式例外，可连问但每问独立成段）。不替 human 做决定——推荐可以给，锁定必须 human 点头。

## 5. Phase 3：锁定前自检（七问）

1. 每个决策点都有 human 的明确确认吗？（"嗯"算，记录原话）
2. 决策之间有矛盾吗？
3. 有没有 🏳️ 的决策点 human 实际可以拍板而我没问？
4. 约束（预算/时间/兼容性）都落进决策树了吗？
5. 领域特有的已知瓶颈/历史教训，都作为约束写进去了吗？（绑定层在编译时注入本条实例清单）
6. 术语对齐日志里每个冲突都有统一结论吗？
7. 如果明天另一个 Agent 冷读这份决策树，它能不问任何人就开始执行吗？

## 6. Phase 4：写盘

决策树写入 **NMH 文档**（路径由绑定层定义），格式：

```markdown
# {需求主题}
状态: 🔓 探索中 / ✅ 已锁定
日期: YYYY-MM-DD
参与者: {human} ↔ {agent}

## 决策树
[D1] {主题}
  选项: ...
  锁定: {human 的选择 + 原话}（时间戳）
  来源: {file:line / CAP-STORE ref / 外部文档 / human 原话}   ← 事实断言必填
[D2] ...

## 约束
- {硬约束}

## 术语对齐日志
| 术语 | human 含义 | Agent 理解 | 统一后 |

## 学习摘要
- 分享的域知识: {Agent 分享了什么}
- human 的提问: {暴露的知识缺口}
- human 理解程度: {判断}
- 下次 NMH 可跳过: {已懂的}
```

**学习摘要的用途**：下次同一 human 的 NMH 时读旧文档——不重复教学。学习闭环的协议层最小实现。

## 7. 锁定规则（反应表）

| human 反应 | 节点状态 | 动作 |
|-----------|---------|------|
| 确认（"就 A"/"可以"） | ✅ 锁定 | 记录原话 + 时间戳 |
| 修改（"A 但是 X 要改"） | ✅ 锁定（修正版） | 记录修正 |
| 否决（"都不对，应该是 C"） | ✅ 锁定（C） | 记录，检查下游节点依赖 |
| 搁置（"这个先不管"） | 🏳️ | 显式搁置，标注执行中遇到必须处理时的升级路径 |
| **未取得可验证来源** | 🏳️ | 事实断言必须带来源（文件+行 / CAP-STORE ref+指纹 / 外部文档 / 人类原话）。**先检索（文件/代码/文档/API），检索不到 → 🏳️**；"我记得/我知道"不是来源 |

**"Agent 会不会"不是判定对象。** 不要求执行体自评知识边界（LLM 无法可靠内省：幻觉答案常伴随高置信 [E2]）——只要求一条可机械检查的纪律：**每个事实断言都带可解析的来源；给不出来源 = 🏳️（fail-closed）**。审核方抽查来源（见 §05-NMA Checklist），而不是询问模型"你确定吗"。

**全部节点 ✅ 或 🏳️（无 🔓）= NMH 完成。**

## 8. 执行期随时问（ad-hoc decision request）

锁定不是终点：执行中遇到会改变结果的未知，**当场问**，不攒到收尾报告，也不静默假设。

### 8.1 先分类，再决定问不问

| 情形 | 动作 |
|------|------|
| 所有可行选项指向同一动作 | **直接执行**；把所选假设写入决策日志（显式假设，可审计） |
| 选项导致不同动作、且答案会改变结果 | **问**（结构化请求，见 8.2） |
| 请求本身不可行 / 约束互相冲突 | **提出最小代价的约束修复方案**，一并请求确认 |
| 答案可从现有文件/代码/文档/API 查证 | **先查证**（继承 grill-me 规则）；查不到才问 |

判据是"**答案是否会改变动作**"，不是"我是否有把握"——不依赖自评置信度。

### 8.2 请求格式（结构化，一个请求一个决策）

- **问题**：一句话，指向具体决策点（`[D{n}]` 或执行中新发现）
- **选项**：2–4 个，每个写"选它会发生什么"
- **推荐**：一项 + 一句理由
- **影响**：选错的代价（什么会返工）
- **期限**：默认 24h；超时兜底（默认维持原锁定 / 最保守选项）并记录
- **合并**：同一决策面的多个小问题合并为一个请求；不得连环追问

### 8.3 通道与通知

- 请求经 **CAP-ATTN** 落 CAP-STATE（`kind=decision` + `options[]`），应答面必须是**持久展示面**（CAP-ATTN W5：待办卡片/审批页/弹窗；群聊 @mention 不算）
- 同时经 **CAP-NOTIFY** 发代码级事件（V5 可订阅）；IM 文本只是派生视图，不是唯一通道
- 应答写入 CAP-STATE 后，等待方**从状态恢复**（可重放，不靠聊天记忆）

### 8.4 记录

应答结果追加为演化节点 `[D{n}-e{k}]`：选项 + 原话 + 时间戳 + 触发原因。超时未答也记录兜底动作。

## 9. 并发 NMH

同一 Agent 同时多个 NMH → 每个独立成文档、独立状态。human 切换话题 → 当前 NMH 标"挂起"（不是取消），新话题新文档。

## 10. 演化（锁定后可变）

锁定 ≠ 冻结。演化 = **追加，不覆盖**：`[D{n}-e1] {新约束}（时间戳，触发原因）`

- **触发**：执行中发现新约束 / human 有新想法 / 外部条件变化
- **联动**：受影响下游节点回到 🔓，需重新确认
- **边界**：影响 1-2 个节点 → 演化；影响 >3 个节点或改变核心方向 → 新建 v2 文档（旧文档保留为审计记录）

## 11. 锁定后的流转

NMH 输出（锁定决策树文档）= 任务生命周期的输入（§06-LIFECYCLE）：
- 单团队：决策树 → leader 拆解派发
- 跨团队（仅 single_user）：决策树 + 需求简报 → §07-HANDOFF

**协议只保证**：锁定的决策树以文件形式存在（CAP-STORE），且下一层收到的第一个输入是它。

## 12. 禁止 / 必须

- ❌ 不替 human 锁定（推荐可以，点头必须 human）
- ❌ **无来源不断言**：任何事实断言没有可解析来源时不构造 locked 节点（默认 🏳️）
- ❌ 不编造领域知识填 🏳️ 节点
- ❌ 不在锁定前开始执行（探索可以小步验证，产出必须等锁定）
- ❌ 不把执行期未知攒到最后，也不静默假设（假设必须显式写入决策日志）
- ✅ 每次 NMH 必出文档（哪怕 10 行）——文件即契约
- ✅ 学习摘要必填（学习闭环的最小义务）
- ✅ **弃权是合法完成态**：🏳️ 与 ✅ 同样计入完成；不得因弃权惩罚执行体（奖励诚实弃权，惩罚编造）
- ✅ **spec 结构化**：NMH 锁定的 spec 必须含 `goal / acceptance[]（结构化 acceptance_criteria）/ out_of_scope / decision_class`（§08-CONTRACT）——自然语言 acceptance 是 C-3 一致性检查判不了的地带，结构化字段让规则层能机械判定
