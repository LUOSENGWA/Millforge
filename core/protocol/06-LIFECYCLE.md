# 任务生命周期契约

> v1.0
> 从 NMH 锁定（或 human 直接三要素指令）到任务闭环的完整契约。每层编排角色（arbitrator/leader/worker）遵守同一套，粒度不同。

## 1. 递归拆解模型（每层都是 mini-编排者）

```
human → [arbitrator] → leader → worker → spawn（子执行单元）
         NMH        NMH/路由     NMA 派发    直接三要素
        大拆解       —          中拆解      小拆解
```

| 层 | 输入 | 拆解粒度 | 输出 | 验收方式 |
|----|------|---------|------|---------|
| arbitrator（single_user） | NMH 决策树 | 团队级（哪个团队、什么顺序/并行） | 路由 + project 创建 | leader 汇报 |
| leader | 决策树 / arbitrator 指令 / human 直接指令 | 任务级（2-N 个 task，DAG/顺序） | 派发（三要素 + task spec） | worker 交付件 + NMA 验收 |
| worker | task spec | 原子级（2-4 个 spawn 子任务） | spawn 子任务 | 自己审查 spawn 产出 |
| spawn | 原子任务描述 | — | 产出文件 | worker 审查 |

**每层核心循环同构**：收到任务 → 判来源（human → NMH；Agent → NMA 消息校验：类型 + 三要素 + refs）→ 确认理解 → 拆解 → 派发下一层 → 验收整合 → 回报上级。

**Worker 上下文隔离原则（协议级）**：worker 的 native session **只做调度 + 审查**——拆解、派发、验收、整合。所有实现工作通过 fresh-session 子执行单元完成，子单元从**文件**读上下文（不占对话历史），产出写入文件后销毁。三层缓存链路：共享存储（spawn 读上下文）→ 运行时自动 offload（执行中落盘）→ 硬件 KV cache（兜底）。**违反此原则 = 上下文超限的根因**（L4 测试三次实证）。各角色的单轮非推理内容上限、软/硬重置阈值与按需装载并发数，按 `12-REDLINES §5.2` 的 S/M/L 档执行。

**派发三要素**（结构化派发的必填字段，见 §05-NMA §3 `DELEGATE`）：任务目标 / 验收标准 / 交付位置。缺任一项 = 派发无效，接收方有权退回。

## 2. 完成信号（TASK_COMPLETED）

worker/leader 完成任务 → 发 **TASK_COMPLETED** 信号（room @上级）：

```
@{leader} TASK_COMPLETED: {task-id}
产出: {artifact 路径}
关键结论（3-5 条，一句话一条）:
1. ...
2. ...
```

**关键结论是强制项**——它是验收原材料 + 跨团队 handoff 原材料（§07）+ 上级失忆防御。刚完成任务时总结三句话是顺手的事，事后补不出来。

**基线保证（绑定层提供）**：完成信号应由机制层做状态机副作用（工具提交成功 = 自动发基线完成消息），LLM 负责的是**质量**（结论/摘要），不是"记得报"。"静默没报"必须从机制上不可能。

## 3. 双通道汇报

| 通道 | 职责 | 内容 |
|------|------|------|
| **项目 room 完整汇报**（归档底线） | 全团队 + human 可见，结构化 | 完整结论、产出路径、遗留问题、下一步 |
| **原始通道通知**（送达底线） | human 实际在用的通道（IM/控制台） | 一句话：完成 + 关键结论 + 项目 room 指针 |

- **单团队任务**：原始通道即底线
- **跨团队任务（仅 single_user）**：双通道都走——项目 room 完整汇报 @human + 原始通道通知
- 原始通道的确定：任务派发时记录（绑定层 reply_route 等价物）

## 4. 声明-验证绑定（P3 的执行形态）

任何 Agent 声明"X 已完成/已推送/已建 room/已派发"之前，**同一轮内必须先有对应工具调用且成功**：

| 声明 | 必须先调用的验证 |
|------|----------------|
| 已建 room | room 创建工具的返回值 + 成员检查 |
| 已派发 | 派发工具/消息发送的确认 + 对端认领 |
| 已推送/已归档 | 写入确认（read-back 或工具返回值） |
| 已完成 | 交付件存在（路径检查）+ TASK_COMPLETED 已发 |

**文本输出和工具调用是两条通道**——"说了"不等于"做了"（L4 重测 Manager 五问题核心教训，协议化为所有角色硬规则）。

## 5. 回复纪律（room 噪音控制）

- 只 @mention **需要对方行动**的情况（handoff、blocker、direct question、任务依赖）
- 对纯确认消息（"谢谢"/"收到"/"confirmed"）→ **不回复**（防 ping-pong 死循环）
- 完成报告发出后停止——等新任务，不继续对话
- 同一任务不重复报告完成

## 6. 故障恢复 SOP（编排者不代干活）

```
Worker 异常（Internal error / context exceeded / 无响应 >2min）
  Step 0: 停手。编排者（arbitrator/leader）绝不自己打开 artifact 代做。
  Step 1: 重启该 worker（绑定层机制）
  Step 2: 等待 → 重新派发相同任务
  Step 3: 3 次仍失败 → 升级 human（原始通道，附三次尝试记录）
质量不行 ≠ 故障 → 走 NMA 审核链，不重启
```

**"做了" ≠ 真的做了**：worker 声称的行为必须用系统事实（文件存在、room 消息、工具返回值）交叉验证。

## 7. 权限墙熔断（操作层，模式无关）

**≥2 个 worker 连续报权限错误（allowlist 拦截/无法发言）→ ≤30s 内切换到 DM 私聊通道重路由**，不继续撞墙。权限错误特征：无错误日志、消息静默消失——诊断第一位对比访问控制配置（绑定层职责）。

## 8. 状态机副作用清单（L1/L2 落层，P5 纪律）

以下行为**不允许纯 L3 行为层**实现——必须由绑定层做成状态机副作用或确定性脚本：

| 行为 | 落层 |
|------|------|
| TASK_COMPLETED 基线发出 | L2（提交成功 = 自动副作用） |
| 完成信号写入持久状态（pending_signals） | L2 |
| 决策锁/解锁/重开 | L2（CAP-STATE CAS） |
| 超时判定（2h/24h/窗口） | L2（CAP-TIMER + 派生脚本） |
| 冲突检测/计票/一致性检查 | L2（core/scripts/ 纯函数） |
| NMH/NMA 交互质量（追问/解释/措辞） | L3（行为层，质量增强） |
| 双通道汇报内容生成 | L3（质量层；送达本身 L2 副作用） |

**系统正确性只允许依赖 L1/L2**；L3 失效 = 质量降级，不 = 状态错乱。
