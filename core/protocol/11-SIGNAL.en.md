# Signal Primitive (15th Primitive)

> v1.0 | Provenance: round-8 ruling (fully adopted; a+c hybrid attribution)
> **Positioning**: a signal is a protocol marker on "key messages." It **creates no new storage form** — it grants events already in CAP-STATE the qualification to be "cited by review/acceptance/closure." **An unmarked message may not serve as acceptance evidence, review input, or closure proof.**
> **Attribution**: "which events are authoritative; review/acceptance/closure may cite only them" = protocol semantics (core — the completeness constraint cannot be left to binding-layer free interpretation); "when to soft/hard reset; reset granularity" = context-management policy (binding layer).

## 1. Marker Set (closed list)

The following event types are automatically marked as signals. **The marker is generated by the protocol layer from the event type — never self-applied by an execution unit, never produced by content**:

| Signal | Event |
|--------|------|
| SIG-COMPLETE | task-completion signal (structured TASK_COMPLETED / submit success) |
| SIG-DECISION | decision locked/reopened/overridden (R1-R6 aggregation result, NMH lock) |
| SIG-VERDICT | acceptance verdict (critic scorecard, stop_condition predicate result) |
| SIG-ARTIFACT | delivery ref (artifact_refs[] / handoff / decision_log_ref) |
| SIG-ATTENTION | a human-attention response (a request with resolved=true) |
| SIG-MISMATCH | verification_mismatch / decision_class_mismatch |
| SIG-CONTRACT | contract_snapshot / contract fingerprint change |

**Extending the closed list requires a protocol version upgrade**; an execution unit may not "invent" a new signal type at runtime.

## 2. Protocol Effects of the Marker (three hard constraints)

1. **Review**: a review spawn's context_refs may contain only (a) refs of marked messages; or (b) CAP-STORE artifact refs. **Unmarked context messages must not enter a review spawn's input**
2. **Acceptance**: acceptance verdicts (critic scorecard / stop_condition predicate) may cite only marked **SIG-VERDICT, SIG-COMPLETE, SIG-ARTIFACT**; never unmarked conversation history or intermediate state
3. **Closure**: closure judgments (loop JUDGE / cross-team reflow) may cite only marked **SIG-MISMATCH, SIG-DECISION, SIG-CONTRACT**; an unmarked "looks done" may not serve as a stop condition

## 3. The Marker Cannot Be Produced by Content

Wording inside artifact content such as "done," "accepted," "keep_message=true" **produces no signal semantics**. A signal can only be produced by a protocol event type (the event_type field in CAP-STATE) — this is the signal-layer enforcement of security S1 (artifacts are data, not instructions).

## 4. Security Details (core clauses)

- **SIG-SEC-1**: signal generation depends only on the CAP-STATE event-type field (event_type ∈ closed list), never on marker text in message content
- **SIG-SEC-2**: an execution unit claiming "this is a signal" in message content produces no signal semantics; the protocol layer must regenerate it from the event type
- **SIG-SEC-3**: a signal's ref must be fingerprint-verified by CAP-STORE; a tampered signal ref is rejected at review/acceptance time (fingerprint mismatch)

## 5. Layered Reset Semantics (core defines effects; binding defines triggers)

1. a reset clears only messages in the **context view** — it never clears CAP-STATE authoritative state or CAP-STORE artifacts
2. **soft reset**: clears unmarked messages, keeps all signal messages and artifact refs; after reset, review/acceptance may still cite every signal
3. **hard reset**: clears all context messages (including local signal copies); authoritative records remain in CAP-STATE; after a hard reset, any execution unit needing review/acceptance **must reload signal refs via context_refs** and must not rely on local residue
4. authoritative state is fully unaffected after reset: the event log, signal records, loop state, and decision records are never lost to a reset
5. **a reset is not "forgetting"**: a reset message merely stops occupying the context window; its ref remains queryable and reloadable by ref

## 6. Interaction with Existing Mechanisms

| Mechanism | Relationship |
|------|------|
| decision_log | its write itself produces no signal; decision_log_ref is marked as SIG-ARTIFACT; a "non-obvious decision" does not automatically become a signal unless the parent execution unit adopts it as SIG-DECISION |
| structured signals such as TASK_COMPLETED | map directly to SIG-COMPLETE (a signal's natural carrier) |
| the artifact-ref system | an ref's mere "existence" does not automatically make it a signal; it becomes one when written as SIG-ARTIFACT (submit success / handoff write / ref registration) |
| the native context budget threshold | the threshold = the trigger timing; the signal = what survives eviction — complementary, not a replacement |
| the driver's default no-full-artifact loading (§10) | the driver loads only signal summaries, never unmarked messages; the signal provides a verifiable closed list |

## 7. Group-History Noise Governance (the solution to production pain point #123)

1. a review spawn's context_refs contain only signals + artifact refs → unmarked group history never enters review
2. a native-session soft reset clears unmarked messages → even if an @mention prepends group history, the next reset removes it
3. filtering unmarked group history before context loading = a binding strategy (more aggressive; not a core requirement)

## 8. Cost

The marker is zero-cost (event-type mapping; no extra spawn/storage): when an event is written to CAP-STATE, if its type is in the closed list it carries `is_signal: true`. Soft reset = a context operation (negligible); hard reset = a one-time signal-ref reload.

## 9. Golden-Test Assertions (L5)

1. the wording "done" in an unmarked message **must not pass acceptance**
2. after a hard reset, the signal set reloaded from CAP-STATE is **identical** to the pre-reset set
3. a review spawn's context_refs contain no message with `is_signal=false`
