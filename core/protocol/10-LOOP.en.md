# Loop Primitive (14th Primitive)

> v1.0 | Provenance: round-7 loop-special round (fully adopted, incl. 4 corrections)
> **Positioning**: a Loop has its own spec (goal_ref / stop_condition / budget / convergence_rule), its own lifecycle (iterations), its own driver (accountable orchestrator). It may **contain** tasks, but is not equal to a task.
> The Loop is an upper-level container: tasks inside iterations still go through R1-R6 decision aggregation, NMH spec locking, and critic acceptance. The Loop is only responsible for **repeatedly invoking these mechanisms within budget, until the stop_condition is met or the budget is exhausted**.
> **Why not a state-machine extension**: iteration is not a lifecycle phase — it is repeated execution within the same lifecycle; extending the states would pollute the task state-machine contract, and the "iterating vs executing" distinction means nothing to adapters.

## 1. loop_spec

```
loop_spec = {
  loop_id:                     # unique id generated by CAP-STATE
  goal_ref: CAP-STORE ref,     # points to the human-locked spec artifact (NMH-locked)
  stop_condition: {            # must be an externally decidable binary condition, never a model's subjective declaration
    kind: "deterministic" | "rubric_threshold" | "composite",
    predicate_ref: CAP-STORE ref,   # deterministic predicate / scorecard reference
    threshold?: number            # required for rubric_threshold
  },
  iteration_budget: {
    max_iterations: int,       # hard ceiling, must be human-locked
    max_human_touch: int,      # total human-touch ceiling for the whole loop (incl. R6/NMH/mismatch), not per-iteration
    max_total_spawns?: int,    # total spawn ceiling across iterations (optional)
    token_budget?: int         # binding layer may declare (optional)
  },
  convergence_rule: {
    no_progress_window: int,   # N consecutive no-progress iterations → terminate (a second brake independent of max_iterations)
    progress_signal: "acceptance_delta" | "fingerprint_change" | "score_delta",
    stagnation_action: "freeze_escalate"   # "keep burning budget" is not allowed
  },
  re_plan_rule: {
    enabled: bool,
    max_replans: int,          # hard ceiling (usually ≤ max_iterations/2)
    replan_trigger: "stop_condition_unreachable" | "verification_feedback"
  },
  termination_action: [        # termination actions (ordered)
    {action: "write_decision_record", ref: ...},
    {action: "escalate", to: "accountable", reason: ...},   # exhausted/stalled
    {action: "emit_artifact", ref: ...}                     # success
  ],
  protocol_version: string
}
```

**Key constraints**:
- `stop_condition` **may not be "the model declares completion"** — the model may submit a completion claim, but it is only a candidate that must be verified by an external predicate
- `iteration_budget` must be human-locked (NMH or explicit confirmation); an execution unit **may not self-start a loop nor expand the budget** (a Loop is a budget amplifier)
- `no_progress_window` fires earlier than `max_iterations` independently of it (iterations are not monotonically improving; more iterations do not guarantee convergence)

## 2. The Five Iteration Phases (all driven by CAP-STATE)

```
1. DISPATCH: the driver reads loop state from CAP-STATE and constructs this iteration's task spec
   (goal_ref + previous iteration's mismatch evidence ref + constraint deltas),
   dispatched via CAP-SPAWN as a fresh sub-execution unit (X1 hard isolation, no parent-history inheritance)
2. EXECUTE: the sub-execution unit returns structured results within its X4 bound
   {artifact_refs[], decision_log_ref, self_reported_status}
   — self_reported_status is data, not an acceptance verdict
3. VERIFY: a critic (independent of the sub-execution unit) accepts — not the parent's self-verification
   — the five-clause "verifier ≠ declarer" applies inside the loop as well
   verdict: achieved / not_achieved / undecidable
4. JUDGE: the driver reads the critic result + convergence signal and derives next_action:
   - achieved → STOP(success)
   - not_achieved + budget left + progress → RE-PLAN → next iteration
   - not_achieved + budget left + no progress (convergence_rule hit) → STOP(stalled) + escalate
   - not_achieved + budget exhausted → STOP(exhausted) + escalate
   - undecidable → escalate (R6 attention); never self-judge
5. RECORD: the driver writes {iteration_index, result_refs[], critic_verdict,
   progress_signal, budget_consumed} to CAP-STATE + loop history (append-only)
   — the driver keeps no iteration history in its own context
```

**A re-plan spawn's context_refs** (all four required):
```
[mismatch_evidence_ref,      # the critic's feedback this round
 spec_ref,                   # the human-locked goal
 previous_artifact_ref,      # previous iteration's artifact (for reference, not for copying)
 convergence_trajectory_ref] # the sequence of progress signals so far (prevents repeating ineffective paths)
```

## 3. Driver Semantics

1. loop authoritative state exists **only in CAP-STATE** (current_iteration, budget_remaining, convergence_trajectory, last_verdict, phase) — no execution unit's context is authoritative
2. driver = the **accountable orchestrator** of the loop's scope (team loop → leader; cross-team → arbitrator; single-unit local → its parent). Identity is determined by the CAP-ROSTER accountable query, **never self-declared**
3. the driver **idempotently re-derives** next_action from CAP-STATE on every wake — no session-memory dependence, no independent counters, repeated wakes yield the same result
4. a driver crash/absence does not affect authoritative state; CAP-TIMER wakes via the persisted next_check_at as fallback; absence beyond the declared bound → escalate
5. the driver **may not self-judge the stop_condition as met** — the "met" verdict is read only after the predicate/critic writes it to CAP-STATE

**Native context budget (corrects round 6)**: the driver's native context keeps only iteration summaries ({index, verdict, progress_signal, key_refs[]}); full artifacts are **not loaded by default**; needing the full view → dispatch a review spawn.

## 4. Activation Tiers

| Tier | Activation rule |
|------|---------|
| **simple** | **not activated**. Local retries use a bounded failure loop (≤3 → escalate) |
| **standard** | **conditionally activated**: stop_condition is rubric_threshold or converges only over multiple rounds (e.g. integration verification after parallel multi-file work); pure deterministic one-shot tasks are not activated |
| **full** | **activated by default** (when the goal requires iteration); cross-team feedback loops must use Loop budget and driver semantics |

**Activation is human-locked** (the accountable stakeholder explicitly confirms iteration_budget and stop_condition).

## 5. Cross-Team Feedback Loops (special Loop form, single_user only)

1. **reflow budget**: the handoff consumer's acceptance fails → reflow to the producing team's iteration. Default ≤2 full reflows (the full tier may be human-locked to ≤4)
2. each reflow = a new iteration, **consuming iteration_budget (a shared budget pool, not a free retry)**
3. **anti-ping-pong semantic-stall detection** (compares semantic fingerprints, not round counts): every reflow mismatch carries acceptance_criterion_id + evidence_fingerprint; 2 consecutive reflows pointing at the same criterion with unchanged fingerprint → **semantic stall, terminate and escalate immediately (even if budget remains)**; A→B→A alternation with a different criterion each time → may continue to the budget ceiling, each round recording new-criterion evidence
4. over-budget / semantic stall → handled as R1, accountable ruling (continue / terminate / redefine goal)

## 6. Anti-Bypass Rules (core clauses)

**Anti-fragmentation** (splitting into N simple tasks to dodge the loop budget):
1. ≥2 tasks under the same goal_ref whose artifact references form a dependency chain → **must share one loop container**, consuming the same iteration_budget
2. creating a simple-tier task requires a `fragmentation_justification` ("independently deliverable with no artifact dependency"); no valid justification → classified as an in-loop iteration
3. detection: CAP-STATE aggregates by goal_ref; >3 simple tasks cross-referencing → `suspected_loop_fragmentation` alert

**Anti-padding** (making minimal changes each iteration to dilute cost):
1. progress_signal **must be magnitude-aware**, never a binary "there was a change": acceptance_delta (count of newly passing criteria, 0 = no progress) / score_delta (below min_score_delta = no progress) / fingerprint_change (must be accompanied by a semantic difference; pure formatting change does not count)
2. no_progress_window counting is based on the magnitude-aware signal; N consecutive below threshold → stalled
3. a single artifact change < min_substantive_change (declared by the domain fragment) → tagged `low_yield`, convergence trajectory down-weighted, consecutive low_yield counted into no_progress_window

## 7. Corrections to Other Rulings

- **corrects the W1 idempotency key**: `hash(loop_id + iteration_index + action_type + input_fingerprint)`; out-of-loop tasks use `hash(task_id + 0 + action_type + input_fingerprint)` for compatibility; same iteration + same input = a duplicate request returns ALREADY_RESOLVED; cross-iteration same input = a different request + a "repeated input" alert
- **corrects the human-touch budget**: max_human_touch is aggregated by **goal_ref** (the whole loop); re-planning itself does not touch a human (only a re-plan needing clarification goes to R6)
- **new CAP-SPAWN X4 boundedness**: a spawn must declare a bounded return within its deadline (a structured result or a bounded failure `{bounded_failure: true, reason, partial_refs?}`); **a runtime not satisfying X4 is not a legal binding** (otherwise iteration_budget and CAP-TIMER become meaningless)

## 8. Runtime Driving (not required by the core; implemented by the binding)

The core requires only CAP-SPAWN X2+X4 and CAP-STATE/CAP-TIMER driving. Whether the runtime ships its own internal loop is the binding layer's business.
The generic driver form = **external scheduler (runtime scheduler/timer) + CAP-STATE idempotent derivation script**:
trigger → read CAP-STATE → derive next_action → CAP-SPAWN (X4 bound) → write back CAP-STATE → register the next trigger.
Driver absent → the scheduler keeps triggering → heartbeat beyond the bound is detected → escalate.
