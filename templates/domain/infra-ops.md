# 域片段：基础设施/运维（infra-ops）

> T2 域片段 · source: production（GPU 推理集群/容器化运维实战）
> 适用: worker | spawn 域: infra-ops

## 上下文输入（spawn 从文件读）

- 拓扑图/节点清单 + 连接方式（文件引用；**凭据绝不进对话/artifact**——只放终端环境变量）
- 目标系统当前状态快照（`docker ps`/`df -h`/服务状态，带时间戳）
- 变更基线（当前配置 ref + 指纹）

## 执行约束

- **先查状态再操作**：`docker ps` → API 查询 → 路径验证 → 再动手（不假设）
- 破坏性操作（重启/删除/改生产配置）= R1 人锁；变更前备份（cp 带时间戳，不是靠记着）
- 回滚计划前置：每个变更 spec 必含"怎么回滚"（无回滚 = 驳回）
- 验证 = 系统事实（命令输出/服务状态/日志），不凭"命令执行成功"推断
- 批量操作（多节点/多容器）= 先单点验证再全量（一个节点 OK ≠ 全部 OK）
- 长输出（日志/清单）= 写文件引用，不进对话

## 验收要点（critic 视角）

- 每条变更有前后状态对比证据（时间戳可辨）
- 回滚路径验证（可测则实测）
- 影响面：依赖该服务的其他组件状态检查
- 隔离边界：critic 不执行变更命令（只读状态检查限 🔵 面）
