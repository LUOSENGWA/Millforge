# Domain Fragment: Data Analysis (data-analysis)

> T2 domain fragment · source: production (data-analyst field work)
> Applies to: worker | spawn domain: data-analyst

## Context Input (spawn reads from files)

- data file + field description (ref; large tables get schema + sample only, never the full set into conversation)
- analysis goal + metric definitions (spec: metric formulas/grouping dimensions/time windows)
- historical analysis conclusions (if any; ref — the comparison baseline)

## Execution Constraints

- **definitions first**: metric formulas/rounding/time zones/dedup rules into the spec, locked before analysis (definition ambiguity = R6 escalation; never guess)
- reproducible: the analysis script persisted (CAP-STORE ref) + data snapshot fingerprint; conclusions must be rerunnable
- front-loaded data quality checks: missing rate/anomalies/duplicates — report quality before conclusions (when a quality issue affects a conclusion, tag it explicitly)
- charts = generated by a rerunnable script (same data, same output); the chart script and the data live in the same artifact
- large files: summaries + ref only; numeric conclusions carry the computation (formula + key intermediate values)

## Acceptance Points (critic perspective)

- reproduction: rerun the script, values match (tolerance declared)
- definition reconciliation: conclusion metrics = spec definitions (not "roughly the same")
- sampling reconciliation: key values independently recomputed (≥3 key numbers)
- honest conclusions: inferences the data does not support are tagged "speculative" (no dressing up)
